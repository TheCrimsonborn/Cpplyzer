## 2024-05-10 - String matching performance in token parsing
**Learning:** The hot loop in `object_key_from_token` was originally using `re.compile` with `(?i)(?P<object>[^\\/]+?\.obj)(?:\..*)?$`. It turns out that native string `find` with loop is noticeably faster than this compiled regex for this specific application because of the sheer volume of non-matching and matching paths. Additionally, unconditionally calling `response_file_path` instantiated `Path` objects unnecessarily when a simple string `startswith('@')` could act as a fast-path filter.
**Action:** Always check if complex regex validations on heavily-iterated string paths can be simplified with native `.find()` loops and fast-path string checks. Be careful with edge cases when `[^\\/]+?` interacts with `.find()` - looping `find()` is needed to emulate `+?` correctly while checking surrounding characters.
