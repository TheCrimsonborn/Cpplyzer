## 2024-05-15 - Fast-pathing `object_key_from_token`
**Learning:** `Path` instantiation and `.name` property access in hot loops (like parsing thousands of tokens in compile logs) add significant overhead. Adding a fast path to pre-filter strings missing the `.obj` extension and using string slicing (`rfind`) rather than generating a `Path` object just to extract the basename, resulted in a >20% time reduction in microbenchmarks. A previous attempt at using `@functools.lru_cache(maxsize=None)` here was reverted because caching unbounded distinct strings would lead to a serious memory leak in long-running processes, outweighing microbenchmark gains.
**Action:** In performance-critical paths, especially during string and token processing, prefer fast string checks (e.g., `.endswith()`, `in`, `rfind()`) over heavy object instantiation and regular expressions. Be extremely cautious with unbounded caching (`maxsize=None`) on input streams that can grow indefinitely.
