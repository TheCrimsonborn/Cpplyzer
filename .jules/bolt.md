## 2024-05-22 - Fast-path substring check for regex in log parsing
**Learning:** For case-insensitive checks on long strings (like log tokens), explicitly checking exact string permutations (e.g., `if '.obj' not in token and '.OBJ' not in token...`) is significantly faster than using `.lower()` before the `in` check. Manual string parsing (like `rfind`) can actually be slower than executing the regex on the heavily filtered subset, so avoid replacing simple regex with manual parsing unless carefully benchmarked. Also, avoid unconditionally calling cached functions like `response_file_path` that perform string cleaning and Path object instantiation if it's only relevant for a subset of tokens (e.g. those starting with `@`).
**Action:** When optimizing hot paths involving regex, use fast-path substring permutation checks to filter out non-matches quickly. Ensure functions that do complex parsing (like Path instantiation) are only called when logically necessary, even if they are `lru_cache`d, to save function call and early-return overhead.
